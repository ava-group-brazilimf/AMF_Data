## Purpose

Generate the final, consolidated inventory report that merges all discovery artifacts — scan results, classifications, dependency data, dead code findings, and volume estimates — into a single, authoritative inventory document. This is the master artifact that Gate 1 reviews and all downstream agents consume.

### Mandatory Outputs Checklist

All four outputs below are **required** and must be generated in a **single execution** of `*generate-inventory`. The task is not complete until every file exists and passes validation.

| # | File | Format | Status |
|---|------|--------|--------|
| 1 | `inventory-enriched.json` | JSON | Required |
| 2 | `inventory-report.md` | Markdown | Required |
| 3 | `asis-platform-landscape.html` | HTML | Required |
| 4 | `all-objects-inventory.csv` | CSV | Required |

> **CRITICAL:** Do NOT skip the HTML or CSV steps. All four outputs must be written to disk before presenting the completion message to the user. If any step fails, retry it before proceeding to the next step.

## Execution Steps

### Step 1 — Load All Artifacts

```
1.1  Load inventory.json (required)
1.2  Load classification.json (if available)
1.3  Load dependency-graph.json (if available)
1.4  Load dead-code-report.md (if available)
1.5  Load data-volume-estimate.json (if available)
1.6  Log which artifacts are available vs missing
```

### Step 2 — Enrich Inventory

```
2.1  For each object in inventory:
     - Merge classification data (complexity, effort estimate)
     - Merge dependency data (in_degree, out_degree, critical path)
     - Merge dead code flags (orphan, unused, deprecated)
     - Merge volume data (size, row count, partitions)
2.2  Calculate derived fields:
     - migration_priority (based on dependencies + complexity)
     - migration_wave (based on topological sort)
     - exclude_from_migration (dead code flag)
2.3  Validate completeness:
     - Every object has a unique ID
     - Every object has a type classification
     - No duplicate entries
```

### Step 3 — Generate Summary Statistics

```
3.1  Total objects by type:
     - Tables, Views, Procedures, Pipelines, Jobs, Scripts
3.2  Classification distribution:
     - Simple, Moderate, Complex, Very Complex
3.3  Dead code statistics:
     - Orphan tables, Unused scripts, Deprecated jobs
     - Total excluded from migration scope
3.4  Volume statistics:
     - Total data volume (in-scope)
     - Total data volume (excluded dead code)
     - Estimated transfer time
3.5  Dependency statistics:
     - Graph depth, Hub nodes, Isolated nodes
3.6  Migration wave plan:
     - Wave 1 (independent objects, simple)
     - Wave 2 (moderate dependencies)
     - Wave 3+ (complex, deep dependencies)
```

### Step 4 — Persist Enriched JSON

Save the enriched inventory data as a single structured JSON file.

- **File:** `inventory-enriched.json`
- **Path:** `projects/{project_name}/outputs/upstream/inventory/`

The file must follow the **Output Schema** defined below.
Every object processed in Step 2 must appear in the `objects` array.
Every wave calculated in Step 2 must appear in `migration_waves`.
Every statistic computed in Step 3 must appear in `summary`.

Do NOT omit fields even when their value is zero or null.
Use `null` for truly unknown values. Use `0` for numeric zeros.

This JSON is the **canonical data source** for the MD and HTML steps that follow.

### Step 6 — Generate HTML Report

Using the data already computed in Steps 2–3, generate the executive HTML report.
This step generates HTML only. The Markdown report was already saved in Step 5.

- **File:** `asis-platform-landscape.html`
- **Path:** `projects/{project_name}/outputs/upstream/`

Before generating, read the reference template:
`src/modules/dmf-fabric-agents/upstream-discovery/templates/asis-platform-landscape-tmpl.html`

The HTML must be a single self-contained file.
The numerical values in this file MUST be identical to `inventory-enriched.json` and `inventory-report.md`.

**Style:** Dark theme (#0D0F14 bg). Fonts: DM Serif Display (headings,
italic accent), DM Mono (labels/tags/values), Outfit (body) via Google Fonts.
Accent color amber #F59E0B for AS-IS badge and primary KPI. Secondary colors:
teal #14B8A6 (coverage), blue #60A5FA (semantic), coral #FB923C (gaps),
purple #A78BFA (readiness), red #EF4444 (high risk). All as CSS variables.

**Required sections (in order):**

1. Header — amber badge 'AS-IS Assessment', DM Serif Display title with
   italic accent, subtitle, right-aligned metadata block (Trace ID, agents,
   source platform, target platform, date) in DM Mono.
2. KPI Row — 5 cards with 2px top color bar, large monospace value, uppercase
   label, sub-line. Values: total objects (amber), physical coverage % (teal),
   semantic enrichment % (blue), gaps count (coral), target readiness % (purple).
3. Source Platforms Grid — 2-column grid, one card per discovered platform:
   icon square, name, version, 2x2 attribute grid, risk tag (High/Medium/Low).
4. Data Lineage Flow — horizontal node→arrow chain showing current data flow.
   Each node: system name + tech sub-label. Each arrow: tool label above line.
5. Critical Objects Table — top objects by complexity (max 15 rows). Columns: #,
   name, type tag (colored), platform, dependencies count, complexity mini-bar,
   migration strategy badge (Lift / Refactor / Rebuild).
6. Gaps & Risks Grid — 3-column, each card: impact dot+label, title, desc.
   Border color matches impact (red=high, amber=medium, teal=low).
7. Footer — left: brand text. Right: 'AS-IS Assessment · date'.

Section titles use DM Mono, uppercase, letter-spacing 0.14em,
with ::after pseudo-element line extending to the right.
Hover effects on all cards and table rows (transition: all 0.2s).
No external JS. Single `<style>` block. No unfilled `{{...}}` placeholders.

### Step 7 — Generate CSV Summary

Using the data from Steps 2–3, generate a complete per-object CSV listing every individual object discovered during the inventory mapping.

- **File:** `all-objects-inventory.csv`
- **Path:** `projects/{project_name}/outputs/upstream/inventory/`

**Required columns (in this order):**

| Column | Description |
|--------|-------------|
| `Database` | Source database name (e.g., DWHIAE, BI_STAGE) |
| `Schema` | Schema or namespace (e.g., dbo, PGP) |
| `ObjectName` | Full object name |
| `ObjectType` | One of: Table, View, Procedure, Function, Index |
| `Layer` | Classification layer (e.g., Stage, ODS, DW, Mart, Operational) |
| `Complexity` | Complexity tier: Low, Medium, or High |
| `SourceFile` | Source file where the object was discovered |

**Rules:**
- One row per object — every table, view, procedure, function, and index must appear
- Use UTF-8 encoding with BOM for Excel compatibility
- No duplicate rows
- Sort by Database, ObjectType, Schema, ObjectName
- The total row count must match the `total_objects` field in `inventory-enriched.json`
- Use `Export-Csv` (PowerShell) or equivalent with `-NoTypeInformation`

This CSV is the **canonical flat-file inventory** for stakeholder review, Excel filtering, and import into external tools. It complements the JSON (machine-readable) and Markdown (human-readable) outputs.
