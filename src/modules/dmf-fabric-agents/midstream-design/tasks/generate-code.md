# ⚙️ Task: Generate Target Platform Code

> **Command:** `*generate-code`
> **Agent:** Coda (Code Generator)
> **Phase:** MIDSTREAM | **Gate:** 2

---

## Objective

Generate native target platform code from platform-agnostic pseudocode produced by Logan 🧠. The generated code must be production-ready, optimized, and follow platform-specific best practices.

---

## Prerequisites

- [ ] Pseudocode file available: `pseudocode/{pipeline_id}.json`
- [ ] Target platform configuration available: `target-config.yaml`
- [ ] Pipeline metadata validated by Logan 🧠

---

## Steps

### Step 1: Load Pseudocode

Load the pseudocode JSON from Logan's output and parse the transformation graph.

```
Input:  pseudocode/{pipeline_id}.json
Parse:  sources[], transformations[], targets[], mappings[]
Validate: JSON schema compliance, all references resolved
```

**Validation:**
- All source references exist in metadata
- All target schemas are defined
- Transformation logic is complete (no TODOs)

---

### Step 2: Classify Transformation Pattern

Analyze the pseudocode to classify which code generation pattern applies.

| Pattern          | Detection Criteria                                        |
|------------------|-----------------------------------------------------------|
| Simple ETL       | Single source, ≤5 transformations, single target          |
| Complex Join     | Multiple sources with joins, business key matching        |
| Aggregation      | GROUP BY, window functions, HAVING clauses                |
| SCD Type 2       | History tracking, effective dates, current flag           |
| Incremental Load | Watermark column, change detection logic                  |
| Full Load        | Truncate-and-reload, no incremental logic                 |
| Delta Merge      | MERGE INTO, upsert conditions, match/not-match actions    |

**Output:** `pattern_classification` with confidence score

---

### Step 3: Select Template or LLM Approach

Based on pattern classification, select the code generation strategy.

```
IF pattern_confidence >= 0.85 AND template_exists(pattern):
    strategy = "TEMPLATE"
    Load template from templates/{pattern}-tmpl.md
ELSE:
    strategy = "LLM"
    Prepare prompt with pseudocode + platform context
    
IF has_custom_logic(pseudocode):
    strategy = "HYBRID" (template structure + LLM for custom parts)
```

**Decision Matrix:**

| Confidence | Template | Strategy |
|------------|----------|----------|
| ≥ 0.85     | Exists   | TEMPLATE |
| ≥ 0.85     | Missing  | LLM      |
| < 0.85     | Exists   | HYBRID   |
| < 0.85     | Missing  | LLM      |

---

### Step 4: Apply Platform-Specific Optimizations

Apply automatic optimizations based on the target platform.

**Databricks (PySpark):**
- Use Delta Lake for all write operations
- Apply broadcast hints for small tables (< 100MB)
- Set appropriate partition columns
- Enable auto-optimize and auto-compaction
- Use Z-ORDER for frequently queried columns

**Microsoft Fabric:**
- Use Lakehouse native connectors
- Apply T-SQL optimizations for SQL workloads

**Snowflake:**
- Use Snowpark optimized operations
- Apply clustering keys
